# Космос Proxy — дизайн-система

## 1. Общее направление

Приложение «Космос Proxy» должно выглядеть как самостоятельный современный продукт.

Не допускается ощущение:
- перекрашенного Hiddify;
- копии референсного приложения;
- технического VPN-клиента для специалистов;
- перегруженного интерфейса.

Основной стиль:
- светлый;
- бело-лавандовый;
- минималистичный;
- мягкий;
- премиальный;
- технологичный;
- космический, но без визуального шума.

## 3. Использование оранжевого

Оранжевый не должен быть основным цветом интерфейса.

Использовать только для:
- активного подключения;
- пробного периода;
- важных уведомлений;
- кнопки продления;
- небольших световых акцентов;
- состояния, требующего внимания.

## 4. Градиенты

Основной градиент:
фиолетовый → синий

Дополнительный:
лаванда → фиолетовый

Акцентный:
фиолетовый → оранжевый

Градиенты должны быть мягкими, без кислотных цветов.

## 5. Типографика

Приоритет:
- чистый геометрический гротеск;
- высокая читаемость;
- поддержка кириллицы;
- одинаковое восприятие на Android, iOS, macOS и Windows.

Заголовки:
- крупные;
- жирные;
- короткие;
- без лишних переносов.

Основной текст:
- спокойный;
- с увеличенным межстрочным интервалом;
- без технического жаргона.

Не использовать декоративные шрифты.

## 6. Скругления

Крупные карточки:
24–32 px

Кнопки:
18–24 px

Поля ввода:
18–22 px

Малые элементы:
12–16 px

## 7. Тени

Тени:
- мягкие;
- светлые;
- с низкой непрозрачностью;
- без тяжёлой чёрной обводки.

Карточки должны ощущаться воздушными.

## 8. Космические элементы

Допустимы:
- планеты;
- орбиты;
- мягкие сферы;
- звёзды;
- световые точки;
- глянцевые 3D-объекты;
- тонкие линии движения.

Недопустимы:
- перегруженные галактики;
- фотореалистичный космос на каждом экране;
- чёрный фон как основной;
- слишком яркие неоновые эффекты.

## 9. Главный экран

Главный экран должен содержать:

- логотип и название «Космос Proxy»;
- крупную центральную кнопку подключения;
- визуальный образ планеты или орбиты;
- статус соединения;
- выбранный сервер;
- задержку;
- срок действия подписки;
- простой переход к серверам и кабинету.

Пользователь должен понимать состояние подключения за 1–2 секунды.

## 10. Состояния подключения

Отключено:
- светлая лаванда;
- спокойная планета;
- орбита без активной анимации.

Подключение:
- плавное вращение орбиты;
- мягкая пульсация;
- фиолетовый свет.

Подключено:
- фиолетовый с небольшим оранжевым свечением;
- понятный текст «Подключено»;
- отображение страны и задержки.

Ошибка:
- мягкий красный акцент;
- понятное сообщение;
- кнопка «Исправить автоматически».

## 11. Нижняя навигация

Основные разделы:

- Главная
- Серверы
- Подписка
- Настройки

На мобильных устройствах — нижняя навигация.

На macOS и Windows — адаптивная боковая или верхняя навигация.

## 12. Серверы

Показывать пользователю:

- страну;
- флаг;
- название;
- задержку;
- статус;
- «Самый быстрый»;
- избранное.

Не показывать в обычном режиме:

- протокол;
- outbound;
- proxy group;
- VLESS;
- Reality;
- технические теги;
- внутренние идентификаторы.

## 13. Подписка

Экран должен показывать:

- статус подписки;
- дату окончания;
- количество устройств;
- кнопку продления;
- кнопку обновления данных;
- переход в личный кабинет.

## 16. Hiddify

В обычном пользовательском интерфейсе не должно быть:

- названия Hiddify;
- логотипов Hiddify;
- ссылок Hiddify;
- поддержки Hiddify;
- визуально узнаваемых экранов Hiddify.

Обязательное авторство сохраняется только в разделе:

Настройки → О приложении → Лицензии открытого ПО

## 17. Кроссплатформенность

Все новые компоненты должны:

- работать на Android;
- сохранять совместимость с iOS;
- адаптироваться для macOS;
- адаптироваться для Windows;
- не содержать Android-специфичную логику внутри общих экранов;
- использовать общий Flutter UI;
- иметь адаптивные размеры.

## 18. Запреты для Codex

Codex запрещено:

- копировать референсы один в один;
- менять ядро без необходимости;
- удалять платформенные папки;
- использовать изображения с неизвестной лицензией;
- добавлять секреты и ключи в Git;
- использовать чёрный фон как основной;
- возвращать ссылки и брендинг Hiddify;
- делать массовый редизайн без разбивки на этапы;
- начинать публикацию без отдельного разрешения.

## 19. Порядок работы

Каждый экран создаётся отдельно.

После каждого этапа Codex должен показать:

1. Какие файлы изменены.
2. Что изменилось визуально.
3. Какие платформы затронуты.
4. Какие проверки выполнены.
5. Скриншот или превью.
6. Git status.
7. Git diff --stat.

Без отдельной команды не выполнять релиз и публикацию.
